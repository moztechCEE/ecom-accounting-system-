# B2B 免登入採購需求：本次實作範圍

狀態：2026-09-29 開發中，尚未套用資料庫遷移、啟用公開送單或在 DEV 驗收。

## 顧客與業務流程

1. 顧客在獨立的免登入頁瀏覽已上架且明確同意匿名公開的商品。頁面與公開 API **只顯示建議售價**，小計僅供參考；不揭露常態價、活動價、團購主進貨價、客戶折數、成本或精確庫存。
2. 顧客填聯絡資料、公司、採購單號及品項數量後送出「採購需求」。後端重新檢查每個商品的公開資格並保存當時的建議售價快照，回傳不含聯絡資料與內部價格的不透明受理編號。重送同一請求鍵不重建需求。送出時不建立 ERP 銷貨單、不預留或扣減庫存。
3. 授權業務在員工工作台查看待核實需求，人工核對聯絡資訊並配對既有客戶主檔；無效需求可留原因標記為無效。已處理需求不能被悄悄重新配對。配對只建立受理需求與客戶的關聯，不代表對方已同意報價，也不自動產生銷單。
4. 後續才把已核實需求接入人工核庫、可修訂版次正式報價、顧客驗證後接受、ERP 銷貨單與 WMS。**顧客查看並接受專屬價格所用的驗證管道尚待業務決定**；在此之前，既有登入後報價流程仍是唯一可接受的線上正式報價入口。

## 啟用與驗收邊界

- 匿名目錄與匿名送單使用獨立功能開關；送單還需專用限流密鑰及可信的代理來源設定。所有開關預設關閉。LINE 可用來傳送受理編號，但不得把採購需求 UUID 當成私人價格的授權憑證。
- 本次需以合成顧客與商品測試：未公開／停用商品拒收、只有 MSRP 可見、公司隔離、重送不重建、限流、未知欄位拒收、員工配對權限及審計。其後才做 DEV 具名顧客、公開網頁與人工核實的操作驗收。
- 將訪客需求轉成既有 B2B 正式需求及採用免密碼的私人報價確認，需另有身分驗證、連結效期與撤銷、接受證據及銷單承接測試。在完成前不能宣稱「免登入下單後自動形成 ERP 銷貨單」。
