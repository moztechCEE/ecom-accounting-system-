# 售後工作台整合與低干擾介面交付

2026-10-08。此批承接既有功能盤點、原售後模組整合與收發／維修流程，集中整理工作台入口及操作畫面。正式環境不在本批發布範圍；DEV 的實際 SHA、images、流量與驗收另存部署回執，不能以本文件代替。

## 工作台與共用能力

售後、收發室、維修各有獨立工作區，登入預設依現有資格或本人／公司／瀏覽器偏好選定。主管與兼任同仁可同時勾選授權並切換；頁面與每次後端操作仍核對公司和目前授權。個人費用、請假、薪資入口保留原功能。

| 工作區 | 主要工作 | 案件與實物邊界 |
| --- | --- | --- |
| 售後工作台 | 建立原售後案件、報價、客服交辦、款項及發票進度 | 主單、顧客同意、入帳和客服接手分別記錄 |
| 收發室工作台 | 收件、照片／實物核對、逐件交接與寄回物流 | 系統通知不是本人簽收；交接前原保管人繼續負責 |
| 維修工作台 | 本人簽收、檢修單、方案／估價、維修單、複驗、交回 | 免費與付費顧客維修仍須當版客服／來源放行；公司整新另有流程 |

工作台不再複製產品管理、操作紀錄、LINE 設定或發票系統。人員依權限由原入口處理；售後頁保留相關案件連結、目前節點及真實結果。原 FAQ／知識庫排除於 DOA 原生入口，Claw 頁面操作指南仍保留。

## 介面與草稿

每個工作台只保留一個內容頁名、必要欄位、案件資料及短動作。移除常駐工程旁白、冗長教學、重複流程帶及重複按鍵；基本操作仍須能直接理解。一般教學由「這頁怎麼用」提供，雙語指南與受影響 source hashes 集中更新。全系統規則已寫入 `AGENTS.md`，未修改既有發布規則。

維修頁以品名、案件號、SN／SKU辨識實物，主區填檢修／維修單。桌面作業位於側欄，手機先表單後作業；當版客服、顧客同意、必要款項及庫存／複驗守門保留。儲存草稿、正式提交、已保存版列印、明確取消預留分開。原廠命令送出期間不能收合，拒絕回饋保留在外層；沒有把尚未實跑的保存成功後 GET 重載失敗冒稱為整個父頁已驗收。

收發補建維持 SENT → 指定客服本人 ACCEPTED → 原案件中心建立或核對主單 → 選當版申報品項綁回原 NativeID → RESOLVED。綁回不改原收件單、保管人、位置、RECEIVED、下一位實物接收人。未知結果先查原 body／requestId 的精確回執，不能重建主單或重收同一物件。

實際寄出維持收發室本人保管的 REPAIR／READY_FOR_DISPATCH、真物流與 boolean 實物確認。正式替換出庫只核對既有 POSTED OUT／reservation／替換實物證明，不二次出庫。「寄出同步：待串接」與「既有進度同步」分別顯示；舊 ACK 不能當本次通知、顧客收件或結案證據。

## 帳務方向與尚待外部驗收

建議沿用 ERP 既有對帳能力，另設售後來源的工作清單或篩選，避免第二本帳。工作台呈現同一案件的應收、匯款回報、核對與發票結果；付款確認由被授權人員或未來經驗證的自動對帳事件產生。目前 Source 財務紀錄仍為現有作業來源，未在此介面整理批遷帳或新增帳務模組。

完整 LINE／AI 客服通知尚須確認品牌、官方帳號、顧客 LINE 身分、會話及接收人一致；缺綁定或品牌不符不得送出。品牌分開的發票商戶、ERP 寄出 consumer、虛擬帳號自動對帳、影片／顧客報告及新開票放行契約仍待共同整合。原 Source 各功能可開啟，不代表上述新跨系統契約已完成。

人工核對須涵蓋實際使用者／公司資格、各品牌 LINE 與開票、付款及退款、倉儲／ECOUNT、現場點收與寄回。合成測試和一般 QA 帳號的 DEV 只讀驗收不取代這些結果。
