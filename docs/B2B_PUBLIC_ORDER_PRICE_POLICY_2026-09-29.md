# B2B 公開採購與四種價格：實作邊界

狀態：2026-09-29 開發中的業務規則。此文件不是已上線或已驗收的宣告；公開頁只顯示建議售價已由業務確認，團購主資格辨識方式仍待確認。

## 價格各有用途

| 名稱 | 用途 | 生效條件 |
| --- | --- | --- |
| 建議售價（MSRP） | 對外參考牌價、顧客折數的預設計算基準 | 商品上架及已核准價目版本 |
| 常態售價 | 一般通路的標準成交價格 | 適用通路及價目版本 |
| 活動價 | 特定活動的候選成交價格 | 活動、適用對象、開始與結束時間 |
| 團購價 | 商品提供給已確認團購主的進貨價 | 商品價目設定；套用前須核實該顧客為團購主 |
| 客戶正式報價 | 該客戶與該次需求的實際成交提案 | 人工核庫及身分確認後出具的固定版次 |

前四種價格不得混用 `Product.salesPrice`：Shopify、Shopline、OneShop 訂單匯入都可能以交易明細單價更新該欄。活動價保留各檔期間紀錄；團購價是商品持續的團購主進貨價，與「購買數量達標後才折扣」不同。代理商屬批發客戶，專屬折數或固定價通常比團購主進貨價低，但不把此習慣當成所有商品都必須符合的硬限制。客戶專屬折數、固定價及單次議價與公開價分開管理。

## 採購與報價

1. 公開頁預設只顯示已上架、另經員工勾選匿名公開的商品建議售價及參考小計，不回傳專屬價、成本或精確庫存。顧客送出的是採購需求，保留 SKU、來源行、數量、當時公開牌價、聯絡資料、客戶採購單號及防重複請求 ID；尚不預留或扣減庫存。
2. 員工以已登記聯絡方式或人工核實配對客戶，逐行核庫。系統展示客戶預設折數、SKU 固定價例外、常態／活動價與商品團購主價作為不同來源；**不自動疊加**活動、團購與代理商折數。團購主身分未核實前，團購價只供內部參考，不自動帶入正式報價。
3. 報價編輯器區分「本次報價」與「儲存為未來客戶價規則」。第一版可調整原需求各行的數量、未稅單價與條件；增刪商品仍須建立新需求。送出成 V1 後不可覆寫，修訂成 V2 會使舊版不能再接受。每版保存當時的品項、實際單價、稅與總額快照；價源／折數來源仍需單獨保留可稽核證據。客戶只能接受最新有效版本。
4. 顧客接受後，由業務再次核對可售量並確認接單。ERP 銷貨單必須從**已接受報價版本的行項及金額快照**產生，保留來源需求／報價版次與行 ID，才預留 Corely 庫存並送 WMS。裝箱不等於交運；ERP 接收交運證據後仍待人工核銷正式出庫。已接單的變更應另走變更／取消與預留調整，不回寫原報價。

免密碼瀏覽與送需求不代表公開專屬報價。正式報價連結須驗證已登記聯絡方式，建立限時受限會話，並逐筆確認顧客與報價的關聯；LINE 只作傳送管道。舊客戶可以選擇原有登入入口查歷史，新客戶首次配對由員工覆核。

## 待業務確認與驗收

- 公開 B2B 頁只顯示建議售價，已由業務確認；正式上線前仍須以匿名請求檢查回應欄位與頁面。
- 團購主身分由顧客主檔標記、逐張報價人工指定，或活動參與名單決定；未確認前，系統不自動套用團購主進貨價。團購價本身沒有預設數量門檻。
- 建議售價、常態售價的含稅方式與幣別，客戶折數以建議售價或常態售價為基準；未定前，不把任一價源自動套進正式報價。
- 對外發送一次性驗證採已登記 Email、手機或已綁定 LINE 身分；沒有已驗證通道時由員工人工確認。
- 先以合成顧客 A/B 驗證公開 API 不洩漏私價、活動期間、團購價不對未授權顧客套用、55 折計算、單次議價不改常用價、V1/V2 舊版拒絕、銷貨單精確承接已接受版次、重送不重複預留。之後才做具名客戶與倉庫實務驗收。
