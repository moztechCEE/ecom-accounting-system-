# 售後工作台原生案件介面

本次工作台以「待我處理／全部案件」清單、單一新增案件入口及同頁案件詳情取代六個相同頁面的入口。六類案件維持補寄、商品與配件訂購、檢測維修、換貨、退貨退款及產品問題回報；建立時沿用 Source 的真實初始狀態。

## 介面與流程

- 預設為本人案件與真正送給本人／可認領的維修客服交辦；搜尋及類型、節點、品牌篩選保留本人範圍。
- 全部案件需既有公司範圍讀取權限；新建類型由 ERP 與 Source 帳號權限交集決定。
- 案件詳情分開顯示款項、維修交辦與實物保管。原有收發／維修客服佇列保留在「部門交辦」。
- 需要原有進階操作時，由案件詳情開啟精確案件的 Source 介面；不以清單篩選冒充精確案件跳轉。
- 建立內容及 UUID 在未知送出結果時保持不變；重試不產生第二筆案件。

## 系統分工

`/api/v1/after-sales/tasks` 以 `corely.doa.tasks.v1` 簽名讀取 Source 案件及選項、建立案件。Source 是案件、報價、款項、發票、LINE 與物流的既有資料來源。ERP 補上實際維修客服交辦；本批沒有新增另一套付款、維修或庫存寫入端。

建單產品選項沿用 Source 的產品主檔服務及既有 ID；產品主檔與 ERP 庫存同步仍是現有整合的分工，不以 SKU、名稱或自行猜測 ID 建立關聯。未綁定品牌的舊案顯示為未確認，不推測品牌。

萬博創意科技有限公司是 MOZTECH 與 BONSON 共用的發票開立公司。案件品牌仍需保留以利核對。LINE 仍須獨立品牌的官方帳號設定與經驗證的顧客身分；發票商家共用不代表 LINE 帳號共用。DEV 缺少完整品牌 Login 設定時應明確阻擋綁定／發送，不回退到另一品牌。

## 本批範圍

沿用目前已核准 DEV 的 UI、收發室、維修工作台與資料庫結構。沒有修改 migration、正式服務、真實顧客通知、退款或庫存。Source 的進階操作仍由原系統執行；原生首頁與建單的完成不代表實際顧客匯款、發票或 LINE 發送已驗收。

部署及實際 DEV 驗證的固定 SHA、revision 與回執另於本次 DEV 發布紀錄列明。
