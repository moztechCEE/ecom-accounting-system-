驗收期間發現「收貨後、重新核庫前」的採購摘要仍以未收採購量計算，讓 UI 暫時顯示舊缺口可採購；建單 API 已以 409 阻擋。後續程式修正讓摘要明示 `requiresFreshReview`，UI 顯示「待重核」並停用建單，送出前再讀一次摘要。此修正尚須以**新的** DEV 候選映像驗證；上列 0% 修訂並不包含該 UI 修正。

## 尚未完成的營運驗收

目前報價候選 API 關閉 WMS handover/commands，web 與 API 的 WMS 連結指向已停用的配對測試修訂；因此**不可直接升到 DEV 100%**。須另建正確配對的 ERP/WMS 0% 候選，驗證來源銷單拋轉、裝箱後實交、部分出貨、outbox 重送、人工核銷唯一過帳、SSO／CORS 及回滾，再考慮主 DEV 流量。先前的 60＋40 件試驗屬另一筆合成訂單及舊配對候選，不能充當本輪報價程式的正向接單證據。

正式營運還需要具名員工權限、實際客戶與供應商主檔／價格／條碼／品牌對照確認，以及倉管的實物掃碼、交運和晚間核對。此輪未向供應商或客戶發送 LINE 訊息，也未切正式環境。
